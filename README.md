# Wisp

> 只在近处发生的传递。

Wisp 是一个局域网文件互传工具，用 Flutter 重写 LocalSend 的体验层：
**不联网、不注册、不经过任何服务器**，两台设备在同一 Wi-Fi 下直接点对点传输。

---

## 一、为什么叫 Wisp

`wisp` 原意是"一缕轻烟、一束微光"——轻、短、只存在于附近，散开就没了。
这正是这类软件的行为：文件只在两米之内流动，出了这个房间什么都不剩。

| 维度 | 说明 |
| --- | --- |
| 贴合特性 | 轻量、短距、转瞬即逝，对应"局域网直传、不留痕迹" |
| 重名风险 | 4 个字母的英文实词，不在文件传输/网盘/通讯类目里；与 AirDrop、NearDrop、Snapdrop、LocalSend 均无字形或读音冲突 |
| 复杂度 | 单音节、一个词、五个字母以内，中英文都容易读（"威斯普"或直接叫 Wisp） |
| 可延展 | 图标天然可以做"一束散开的光"，与产品动作（发送）同构 |

视觉语言沿用这个意象：**一个点 + 两道向右散开的弧**，就是"轻声传到隔壁"。

---

## 二、与 LocalSend 的关系

- **协议完全兼容**：沿用 [LocalSend Protocol v2.2](https://github.com/localsend/protocol)（组播 `224.0.0.167:53317`、`/register`、`/prepare-upload`、`/upload`、`/cancel`），
  Wisp 与官方 LocalSend 客户端可以互相发现、互相收发。
- **重构的是体验层**：信息层级、动效、操作路径、命名与图标全部重做，网络语义保持不变。
- **没有私有格式**：文字消息也按协议惯例落成 `.txt` 传输，不引入自定义信封。

## 三、界面结构

四个一级页面，按使用频率排序：

| 页面 | 回答的问题 | 关键设计 |
| --- | --- | --- |
| 附近 | 我是谁、附近有谁 | 顶部身份卡（名称 / IP / 指纹 / 可见性），下方雷达扫描或设备列表 |
| 发送 | 发什么、发给谁 | 空态是三入口（文件 / 文件夹 / 文字），选好后横向选设备，底部只有一个主按钮 |
| 记录 | 传过什么 | 按天分组，方向用箭头区分，左滑删除 |
| 设置 | 怎么改行为 | 四组：本机 / 接收 / 外观 / 关于，每项都写清"改了会发生什么" |

传输过程是**全屏路由**而不是弹窗：从点击发送到完成是一条不被打断的路径，避免误触关闭造成"是不是断了"的误解。

设置 → 关于 → **更新日志**：每个版本改了什么、当前装的是哪版，一目了然。数据集中在
`lib/core/release_notes.dart`——发新版本时加一条 `WispReleaseEntry`、把
`currentVersion` 和 pubspec 的 `version:` 同步改掉即可，弹层高亮和版本行显示都会跟着走。

设置 → 关于 → **检查更新**：优先读 Release 附件里的 `update.json`
（`releases/latest/download/update.json`，由 CI 在发版时生成，**带四个平台的 sha256**），
读不到再退回仓库根目录那份手工清单，官方源连不上时自动换加速镜像重试。
清单格式与仓库地址见 `lib/services/update_service.dart` 顶部注释
（`WispUpdateSource.repoOwner` / `repoName` 两行指到真实仓库即可启用）。

**一键更新必须校验**：清单给出本平台 sha256 时，下载完逐字节比对；不符就删包、
换下一个源，并明确提示"校验失败"（不会被后续镜像的网络错误盖掉）。清单没有校验值时
拒绝自动安装，只保留「仅下载」——否则等于"从第三方镜像下个 exe 就提权运行"。
无论检查成败，弹层都列出 **官方源 + 全部加速镜像** 的下载入口（前缀代理形式
`https://ghfast.top/https://github.com/...`），由用户自己挑，不做自动切换
（自动改写下载源有供应链风险）。镜像失效就更新 `WispUpdateSource.mirrors` 列表。

设置 → 关于 → **自动检查更新**：频率可选 每次启动 / 每天 / 每周 / 关闭（默认每天）。
到点后台静默比对一次，发现新版本只弹一条提示并存进 `pendingUpdate`，
设置页入口会显示"新版本 v…"，绝不自动下载安装。应用长期不重启时由
30 分钟一轮的兜底轮询放行到点检查；上次检查时间落在 `lastUpdateCheckMs`，
失败也算查过，避免断网时反复请求。手动「检查更新」与自动检查共用这套
闸门（`WispUpdateCadence`），刚手动查完不会被自动检查重复请求。

### 配色（1.0.10 起）

界面、图标、桌面层的通知卡/气泡/球把手共用同一套取值，全部集中在
`lib/core/design/app_colors.dart`；原生层的 `kBrand` / `kText` / `kLine` 等常量
（`windows/runner/flutter_window.cpp` 顶部）与之逐值对齐——**改色必须两边同时改**，
否则会出现"界面青绿、通知卡另一样"的割裂。

| 角色 | 值 | 用在哪 |
| --- | --- | --- |
| 品牌深 / 浅 | `#0E7C86` → `#23A2A9`（渐变） | 主按钮、雷达、进度环、选中态 |
| 点缀珊瑚 | `#FF7A59` | 图标上那颗数据点、服务器类型头像，用量极小 |
| 浅色底 / 卡片 / 分隔 | `#F7F6F2` / `#FFFFFF` / `#E5E2DA` | 暖中性，和图标那层暖白底同源 |
| 深色底 / 卡片 / 分隔 | `#0A0F10` / `#111A1B` / `#233032` | 带一点青的墨色，不是纯黑 |

主按钮禁用态**不靠整体淡化**（青绿压到 45% 透明度在暖白底上会发灰发脏），
而是换成浅底 + 次级文字，一眼能看出"这不能点"。

## 四、动效原则

| 场景 | 处理 | 理由 |
| --- | --- | --- |
| 页面切换 | 340ms 淡入 + 4% 上浮 | 建立层级，不用大幅位移打断视线 |
| 列表出现 | 每项延迟 45ms，最多累计 8 项 | 有节奏感，但长列表不会让人等 |
| 底栏切换 | 指示块 260ms 滑动 + 图标微缩放 + 触感 | 手指和视觉反馈同步 |
| 雷达 | 单控制器驱动三圈，相位差 1/3 | 省资源，节奏均匀 |
| 进度 | 环形 420ms 缓动，数字随弧线走 | 进度不会"跳"，速率文字用滑动采样平滑 |
| 按钮按下 | 0.975 缩放，180ms | 只给"按下去了"的确认，不做花哨回弹 |

所有时长集中在 `lib/core/design/app_motion.dart`，改一处即全局生效。

```bash

```

各平台图标已从 `assets/icon/` 生成好了（含 Android 自适应图标）。改了图标源文件后重新生成：

```bash
dart run flutter_launcher_icons          # 从 assets/icon 生成各平台图标
```

### 端口

| 类型 | 协议 | 默认端口 | 说明 |
| --- | --- | --- | --- |
| 发现 | UDP | 53317 | 组播 `224.0.0.167` |
| 传输 | TCP | 53317 | HTTP(S) REST |

端口可在 设置 → 网络 → 监听端口 里修改。**同机跑两个 LocalSend（官方 + Wisp）必须改端口**，否则两个 HTTP 服务会抢 53317。

防火墙放行 Wisp 的 TCP + UDP 即可。路由器若开启 AP 隔离，设备之间会互相看不见——
这时用首页右上角的「手动连接」输入对方 IP，或在设置里把发现方式切成「扫描」。

**发现不到设备时按这个顺序排查**（前三条是 Windows 上最常见的原因）：

1. **防火墙**：首次运行 Windows 会弹窗询问网络访问，必须勾选「专用网络」并允许；
   如果当时点了取消，去「Windows 安全中心 → 防火墙 → 允许应用通过防火墙」里把 Wisp 的
   **专用/公用** 两列都勾上。TCP 53317 被拦时，对方的 register 打不进来，我们这边永远空列表。
2. **网络位置**：Windows 把 Wi-Fi 标成「公用网络」时，默认策略更严。改成「专用网络」。
3. **两端不在同一网段**：手机连的是 5G 频段、电脑插的是另一台路由器的网线，这类情况扫描也扫不到，
   用「手动连接」直接填对方 IP 最快。
4. **AP 隔离 / 访客网络**：路由器把客户端互相隔离了，任何发现手段都无效，只能手动填 IP。
5. 仍不行时看 设置 → 网络 → 本机地址 是否取到了正确的局域网 IP（有 VPN / 虚拟网卡时可能取错，
   可在「网络接口」里手动指定）。

### 桌面端特性（Windows）

- **苹果风格图标**：squircle 轮廓 + 浅暖白底 + 青绿文件卡 + 珊瑚圆点（三色克制，无三角/箭头，不会看成纸飞机）。由 `tools/gen_icon.py` 精绘生成：1024 源图 → 7 档 ico / Android 自适应前景 / 悬浮球贴图，桌面层的品牌色（托盘徽章、球把手、通知按钮）与应用内主色同源，都是这套青绿，见上节「配色」。
- **关闭最小化到托盘**：点右上角关闭只是收进托盘，后台继续接收文件；托盘右键可退出。设置里可以关掉这个行为。
- **自绘通知卡片**（悬浮球关闭 + 主窗口隐藏时）：托盘图标播放品牌色圆点的呼吸徽章动画（8 帧正弦渐隐渐显），右下角滑入一张与全局设计语言一致的通知卡——询问态（迷你图标 + 标题 + 正文 + 等宽的「接收/忽略」按钮）→ 进度态（进度条 + 百分比）→ 完成态（「打开目录/关闭」），进度更新会自动顺延存活时间；点卡片空白处打开主窗口，其余自动收起，不用系统 toast。
- **通知分流（互斥不打扰）**：三种提醒（应用内弹层 / 桌面通知卡 / 悬浮球气泡）由 `lib/services/notification_router.dart` 一处判定，规则见下节。桌面通知与气泡共用同一个绘制函数（`DrawCardContent`），字体、行距、按钮、进度条完全一致。
- **拖拽发送**（1.0.11）：把文件 / 文件夹从资源管理器拖进主窗口，原生层接住 `WM_DROPFILES` 把 UTF-8 路径回传 Dart，**文件夹自动递归展开**（保留「根目录/相对路径」层级，接收端能还原目录结构），加入待发清单后自动切到发送页。拖进来的内容与已选内容按路径去重，全是快捷方式或没有读取权限的路径时明确提示。自动化验证用 `tools/probe_drop.dart`：自造 `HDROP` 内存块投递真实的 `WM_DROPFILES`，覆盖「原生解析 → 通道 → Dart 展开 → 清单」整条链。
- **历史记录逐条操作**（1.0.11）：点任意一条记录弹出操作面板——**再次发送**（源文件还在原位时，把文件放回待发清单并对端仍在线时自动选中，旧记录没有存路径则提示）、**打开所在目录**（入站记录直达落盘目录）、**删除这条记录**（只删本机记录，不影响已传文件）。出站记录保存源文件路径、入站记录保存落盘目录与对端 IP，旧版本的历史记录缺这些字段也能正常显示，只是没有对应操作。
- **通知分流规则**（判定只看两个维度：主窗口「可见且是当前激活窗口」、悬浮球是否启用）：

  | 悬浮球 | 主窗口 | 提示方式 |
  | --- | --- | --- |
  | 未启用 | 开着且是激活窗口 | 应用内弹层 |
  | 未启用 | 没开 / 开着但被切走 | 桌面通知卡 |
  | 启用 | 开着且是激活窗口 | 应用内弹层 |
  | 启用 | 没开 / 开着但被切走 | 悬浮球气泡 |

  任何时刻主窗口重新获得焦点（点任务栏、Alt+Tab、点通知卡空白处），桌面上的通知/气泡立刻退场，改由应用内弹层接管。气泡位置跟着**可见内容**走：球展开时贴球体、吸附缩成把手时贴把手，朝远离屏幕边缘的一侧弹出，放不下就翻面，最后统一夹回工作区。
- **桌面悬浮球**（设置 → 系统 → 桌面悬浮球）：GDI+ 逐像素 alpha 渲染的圆形球体（带柔和投影），可任意拖动；首次启用出现在桌面右下角，**拖动后的位置会被记住**，重启 / 重新启用后原地恢复（含吸附状态）；拖到屏幕边缘自动吸附并**缩成一个小把手**，鼠标悬停（延时可在设置里调：立即/0.3/0.8/1.5 秒）自动展开，鼠标离开后自动缩回；有文件请求时自动展开并播放呼吸动画提示，点球弹出气泡——询问接收 → 传输进度 → 完成后询问打开保存目录，全流程不用打开主窗口。
- **最小窗口 420×690**：宽度限制来自布局（再窄会错位），高度则按「刚好完整显示」标定——最窄宽度下首页（页头 + 身份卡 + 雷达 + 说明 + 「输入 IP 直接连接」按钮）内容高 617，加上 71 的底部导航正好 688。所以 690 之下首页一屏放得下、不需要滚动，再矮就会把按钮挤出首屏。`test/goldens/14-min-window.png` 与其中的 `maxScrollExtent == 0` 断言会盯着这条线。
- **横竖屏自适应**：竖屏保持底部导航 + 单栏（手机观感）；横屏 / 宽窗口自动切到**左侧导航栏 + 限宽居中的多栏布局**——不是把元素拉宽，而是重新排布：附近页设备变两列网格、发送页左「发什么」右「发给谁」双栏、设置页分组两列、传输页内容居中限宽。判定见 `lib/ui/responsive.dart`（`isWideLayout`，以 orientation 为准）。
- **服务守护**（设置 → 系统 → 服务守护）：可选安装一个 Windows 服务（WispKeepAlive）。应用被误关、崩溃时自动拉起，开机登录后自动恢复；托盘「退出」属于用户主动行为，服务会尊重（写入标记文件，不再拉起），下次手动启动或重新登录时自动解除。安装/卸载各触发一次 UAC 授权。装好之后会多出一行「**重启守护服务**」——服务卡在停止中、或应用被反复拉起时用它（`sc stop` 之后要等约 3 秒 SCM 才允许 `sc start`，代码里用 `ping -n 4` 等这段，比 `timeout` 命令在无控制台时可靠）。

### 发现机制（与官方 LocalSend 互通）

1. **组播 announce**：向 `224.0.0.167:53317` 广播自己的信息（UDP JSON），启动时连发 5 次再转 3 秒心跳；
2. **单播 register 回应**：收到对方 announce 后，用 HTTP POST /register 单播回应（声明的协议不通会自动换另一种）；
3. **接收 register**：对方主动来握手时，把它的信息收进设备列表——**这一步是发现官方客户端的唯一途径**（官方只回单播，不再发组播）；
4. **网段扫描兜底**：逐个私网地址 POST /register，并发 32 路、单点 1.2s 超时，可设置周期（15/30/60 秒）。

这条链路上有几个不显眼但致命的坑，都已经修掉，改动时别再退回去：

- **UDP 必须绑 `anyIPv4`**，不能绑本机单播地址。绑单播地址时组播报文的目的地址是 `224.0.0.167`，能不能收到完全看系统把组播组挂到了哪块网卡——表现就是「有时能发现、有时一台都看不到」。
- **组播出口必须钉在连局域网的那块网卡上**（`IP_MULTICAST_IF`，见 `_pinMulticastInterface`）。装了 VPN / Hyper-V / WSL 之后系统默认路由往往不走物理网卡，announce 从错误网卡发出去，局域网里的官方客户端一个包都收不到——这正是「Wisp 能看到对方、对方搜不到 Wisp」的成因。Dart 的 `multicastInterface` 至今没实现（调用直接抛 `UnimplementedError`），只能走 `setRawOption`；`IP_MULTICAST_IF` 常量 Windows/macOS/iOS 是 9、Linux 是 32。
- **不要往 `255.255.255.255` 补发广播**。Windows 上打到不可达广播地址会积累 ICMP 错误，下一次 `receive()` 直接抛异常，反而把组播 socket 拖进「收不到也发不出」的状态。
- **`receive()` 要 try-catch**，并且一次 `read` 事件要排空接收队列（`while (receive() != null)`）。一次事件可能对应多个数据报，只取一个就走会丢掉同刻到达的其它 announce。
- **socket 要能自愈**：连续 3 次发送失败或 stream 报错就关掉重建（延迟 2 秒），别让发现功能永久静默。
- **`multicastLoopback` 必须为 true**。它是发送端选项，关掉之后连本机其它进程都收不到——同机跑官方客户端做对照测试时，双方会彻底看不见彼此。
- **组播端口固定 53317**（`WispProtocol.multicastPort`），不跟随自定义 HTTP 端口；用户把监听端口改成别的值后，组播仍要在协议端口上收发。
- **不按「本机 IP」过滤来包**，自己的包靠 fingerprint 比对排掉。否则同机的第二个实例永远发现不了。
- **设备 60 秒未刷新自动下线**（`AppState._sweep`），离线设备不会一直挂在列表里。
- **本机地址变化自动重建链路**（同上，每 15 秒巡检一次）：换 Wi-Fi、插拔网线、VPN 启停后组播 socket 还绑在旧地址上就永远发现不到人，以前必须重启应用。

设置 → 网络 → **发现状态** 会直接给出结论：组播有没有加入、最近一次广播发在什么时候、最近一次收到别人的广播是什么时候。对方搜不到你时先看这一行——「广播尚未发出」是出站问题，「暂无广播」是入站问题（路由器隔离或防火墙）。

### 识别用户名（可选）

设置 → 本机 → 识别用户名。规则是**同名才互相可见**（去掉首尾空格、忽略大小写）：

- 你填了名字：只看得到填了同一个名字的设备，**也只有它们看得到你**；
- 你留空：只看得到同样留空的设备——设了名字的设备会互相隐藏，不会出现在你的列表里；
- 官方 LocalSend 没有这个字段（等同于留空），所以设了名字之后就看不到它，它也看不到你。

这条规则在四个地方同时执行，少一处就等于没设：

1. 组播/扫描收到设备信息时（用户名不同：不记进列表，也不回 `register`）；
2. 本机服务端的 `/register`（对不上直接 403，否则对方扫一遍网段就知道我们在）；
3. 本机服务端的 `/prepare-upload`（对不上 403，防止拿着旧记录或组播里看到的地址直接推文件）；
4. 界面列表（兜底，手动连接也走这条）。

**能保证什么、不能保证什么**：它挡的是"同一局域网里误看到别人"和"随手就能把文件推给你"，
不是加密意义上的隔离——组播报文本身是广播的，同一网段抓包仍能看到设备名和 IP；
旧版本客户端（≤1.0.21）没有这套规则，仍可能把你显示出来。真要隔离，靠 VLAN 或热点。

### 稳定性与资源占用

桌面端是要长期挂着的，所以凡是"会一直涨"的东西都设了上限：

| 项目 | 上限 | 说明 |
| --- | --- | --- |
| 传输历史 | 120 条 | 磁盘与内存同步截断，之前只有磁盘截断、内存里一直涨 |
| 会话列表 `sessions` | 只留进行中的 | 结束的会话在 `_finishSession` 里清掉 |
| 去重集合 `_finished` | 256 条 | 超过就整份重置，它只用于"只记一次" |
| 文件 token 索引 | 随会话释放 | `_dropSession` 同时清 `_tokenIndex`，否则每次传输都留一撮 |
| 原生诊断日志 | 512 KB | 超了整份重写；渲染每帧失败时不设限能写满磁盘 |
| 设备列表 | 60 秒 TTL | 离线设备自动下线 |

另外两处：

- **失败/中断的接收会删掉半截文件**。以前 `_handleUpload` 出错只关流，下载目录里会慢慢堆满残缺文件。
- **UDP 组播 socket 能自愈**：连续 3 次发送失败或 stream 报错就关掉重建（延迟 2 秒），不会一次 ICMP 错误就让发现功能永久静默。

上传是流式落盘的（`await for` 逐块写 `IOSink`），不会把整个文件读进内存；速度采样用滑动平均而不是攒点列表。

### 受控端到端自测入口（1.0.9）

界面上的「选设备 → 选文件 → 发送」必须点系统文件对话框，自动化成本极高
（`SendInput` 对 `IFileOpenDialog` 无效）。所以发送链路改成可以走命令行：

```bash
# 全量自测：内置接收端跑一次真实发送 + 检查三类通知是否真的弹出来
wisp.exe --wisp-selftest --wisp-report=C://temp//selftest.json

# 只发一个文件给指定设备（跨机验证用；官方客户端会弹接收确认）
wisp.exe --wisp-send=192.168.0.168:53317 --wisp-file=C://a.zip
wisp.exe --wisp-send=192.168.0.168:53317 --wisp-file=C://a.zip --wisp-https
```

- 结果写进 JSON 报告（GUI 子系统没有控制台，报告文件是唯一可靠输出），
  退出码 0 = 全部通过。实现见 `lib/selftest/selftest.dart`。
- `--wisp-selftest` 的四步：`send_loopback`（96 KB 随机数据逐字节校验，内置接收端
  **严格校验会话号与令牌**——1.0.11 之前它来者不拒，把"发送端拿本地会话号上传"的
  bug 掩盖了）、`toast_visible`（通知卡必须可见且完整落在工作区内）、`bubble_visible`
  （气泡可见、不越界、不压住悬浮球）、`ball_hidden_bubble`（把手态气泡位置）。
- 断言全部基于原生窗口的真实矩形（新通道 `debugWindows`），不靠截图肉眼看。

另有 **TLS 端到端专项**（`test/lan_tls_test.dart`）：接收端用真 `ReceiverService`
（加载内置证书 → `bindSecure` → 签发 token → 落盘），发送端跑在独立 isolate 里绕开
测试桩的 HTTP 拦截，192 KB 随机数据走真实 TCP + TLS 逐字节比对。这条测试在 1.0.11
第一次把"发送端必须用对端签发的会话号上传"暴露了出来。

### 与官方客户端的实测互通（1.0.8）

同机装官方 LocalSend 1.18.2（HTTPS-only，占 53317）+ Wisp 改端口 53318，双向实测：

| 方向 | 证据 |
| --- | --- |
| Wisp → 官方 | 官方日志每 3 秒 `[DISCOVER] WISP-TEST (192.168.0.185)`；官方「发送」页出现 **WISP-TEST** 设备卡（`HTTP` `Windows` 标签） |
| 官方 → Wisp | Wisp「附近」页出现 **MS-7B54**（本机官方实例）；同网段另一台真机 **巨大的梨（192.168.0.168）** 也出现在列表里 |

两个结论值得记住：

1. **官方的 announce 不出现在本机组播回环上**，被动嗅探只能看到 Wisp 自己的包；
   Wisp 之所以仍能发现官方，是因为官方收到 announce 后会**单播 POST /register 回应**
   （`_handleRegister` → `onRegistered` 直连 `_upsertDevice`）。所以这条单播路径是
   发现能力的关键，不能当"冗余逻辑"删掉。
2. **官方「接收」页不显示设备列表**（源码 `receive_tab.dart` 只有身份卡与快速保存开关），
   设备只出现在「发送」页。看到接收页空着不代表没发现。

同机互传这条路走不通：向本机官方实例 POST prepare-upload 会被立刻断开
（`WinError 10053`），推测是它对来自自身 IP 的请求有保护性拒绝。跨机传输本机未实测
（网内另一台是真机但不是测试机，不便发文件），所以"发送"能力仍以 `probe_send.py`
的协议级验证 + 跨机发现为准。

### 会话号 bug 与真 TLS 链路（1.0.11）

`test/lan_tls_test.dart` 第一次跑就抓出一个被掩盖了很久的 bug：**发送端上传时一直带
自己的本地会话号，从不用对端 prepare 应答里签发的那个**——自测里的假服务器不校验
会话号，所以 `send_loopback` 从 1.0.9 起一直是绿的，而真 `ReceiverService` 会直接回
403。已修复（`TransferSession.remoteSessionId`，上传与取消都改用它）。

修完之后的验证边界（如实记录）：

- **真实 TCP + TLS 已验**：`lan_tls_test` 里接收端是真 `ReceiverService`（内置证书 →
  `bindSecure` → token 校验 → sha256 → 落盘），发送端走独立 isolate 的真 socket，
  192 KB 随机数据逐字节一致；`--wisp-send` 对运行中的本机实例（走 192.168.0.185
  网卡地址）同样通过。
- **跨机仍未实测**：192.168.0.x 全网段扫 53317 只有本机在听（那台真机没开
  LocalSend），Tailscale 里的另一台 Windows（thinkbook-14）离线。等一台真机配合时，
  跑一次 `wisp.exe --wipsend=<ip>:53317 --wisp-file=<文件> --wisp-https` 即可补上。

## 八、已知取舍

1. **证书**：1.0.11 起内置一张 10 年期自签证书（`assets/certs/`，所有安装共用同一张，
   `tools/gen_cert.sh` 可换发），「加密传输」默认真正走 TLS；证书缺失或私钥异常时自动
   退回 HTTP，设置页如实标注，不假装安全。
2. **指纹信任**：局域网直连无法走 CA 链。1.0.20 起，发送端在 TLS 握手时要求
   "对端证书的 SHA-256 等于它声明的 `fingerprint`"，网段扫描与手动连接同样比对，
   对不上就断开（以前是任何证书都放行）。

   **这套校验的边界必须说清楚**，别把它当成"设备认证"：

   - 协议 §2 规定 HTTPS 模式下 `fingerprint` 是证书哈希，但 Wisp 历史上一直上报
     32 位随机串（当作设备 ID 用）。所以 1.0.21 起只对**形状是 64 位十六进制**的
     声明做比对，其余视为"设备 ID，不是证书声明"——否则每台真实设备都会被判成
     "证书与声明不符"（1.0.20 就栽在这：设备被踢出列表、横幅反复刷）。
   - 内置证书是**构建时生成、随安装包分发**的，所有 Wisp 安装共用同一张证书，
     它在仓库里公开可读。因此"证书 == 声明的哈希"挡不住有心人，只挡得住
     "随手换张证书的中间人"。
   - 接收端**无法**验证发送方：入站请求的 `request.certificate` 只有在服务端索取
     客户端证书时才非空，而 Dart 的 HttpClient 不支持配置客户端证书。

   真正的修复是给每台设备生成**独立证书**，并把 `fingerprint` 改成证书哈希，
   再叠加首次连接固定（TOFU）。在这之前，别在不可信网络上开自动接收。
3. **并发**：上传固定两路并发。更多并发在机械硬盘和弱网下反而掉速，实测两路最稳。
4. **历史**：只存本机、只存 120 条、可一键清空，不做云端同步。
5. **更新包完整性**：清单里的 sha256 由 CI 发版时计算，一键更新前逐字节比对。
   这不是签名——防的是"下载损坏"和"第三方代理投毒"，不防"清单本身被换掉"。
   彻底解决要给安装包做代码签名（Windows Authenticode / macOS 公证），目前未做。
